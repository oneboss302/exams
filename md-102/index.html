The MD-102 Intune guide

MD-102 is an Intune exam. Almost every question is "which Intune feature, policy type, or enrollment method meets this requirement." The hard part is the many similar-sounding options: join types, Autopilot modes, Android enrollment profiles, remote actions, and app protection vs app configuration. This guide puts each set side by side.

  • Expect "minimize administrative effort" on most questions. The answer is usually the built-in Intune feature, not a script.
  • Platform details matter. iOS, Android, macOS, and Windows each have their own enrollment methods and profile types.
  • Microsoft Learn is available during the exam (open book). Use it sparingly.

04 · Prepare infrastructure · 20–25%

Device infrastructure cheat sheet

Join typeDevice ownerSign in withUse when
Entra registeredUser (BYOD)Local or personal account, work account addedPersonal devices that need access to work apps
Entra joinedOrganizationEntra accountCloud-first corporate Windows devices. Default for Autopilot.
Hybrid Entra joinedOrganizationOn-prem AD accountDevices still need on-prem AD (GPOs, legacy apps). Needs Entra Connect and line of sight to a DC.

Groups

  • Dynamic device groups use rules such as device.deviceOSType -eq "Windows". Need Entra ID P1.
  • All Autopilot devices: device.devicePhysicalIDs -any (_ -contains "[ZTDId]").
  • Autopilot devices with a group tag: device.devicePhysicalIds -any (_ -eq "[OrderID]:Sales").
  • Dynamic membership updates take time. Assignment filters are evaluated at check-in and are faster for targeting.

Windows enrollment

  • Automatic enrollment: Entra ID → Mobility (MDM and WIP) → Intune → MDM user scope = Some or All. Entra join then enrolls automatically.
  • Enrollment restrictions: platform (allow or block platforms, block personally owned) and device limit (default 5 per user, up to 15).
  • Device enrollment managers can enroll up to 1,000 devices (shared or bulk scenarios).
  • Hybrid-joined devices can auto-enroll through a GPO, or co-management with Configuration Manager.

Apple enrollment

  • An Apple MDM push certificate (APNs) is required for any Apple management. Renew it yearly with the same Apple ID or every Apple device must re-enroll.
  • Corporate: Automated Device Enrollment through Apple Business Manager. Supervised, zero-touch, and users can't remove management.
  • Personal (BYOD): account-driven user enrollment (separate managed APFS volume, privacy-preserving) or device enrollment through Company Portal.
  • Apps and Books (VPP) location token from Apple Business Manager for licensed app deployment.

Android Enterprise

  • Personally owned work profile: BYOD. Work apps in a separate profile, and IT can't see personal data.
  • Corporate-owned work profile (COPE): corporate device with personal use allowed.
  • Fully managed (COBO): corporate device, one user, work only.
  • Dedicated (COSU): kiosks, scanners, single-app or multi-app lockdown, no user affinity.
  • Bulk corporate enrollment: Google zero-touch or Samsung Knox Mobile Enrollment, or QR code and token. Requires a Managed Google Play binding.
  • Android device administrator is legacy. Don't pick it.

Intune RBAC

  • Built-in roles: Policy and Profile Manager, Application Manager, Help Desk Operator (remote tasks), Read Only Operator, Endpoint Security Manager, Intune Role Administrator. Intune Administrator is an Entra role with full access.
  • A role assignment has members (admins), scope groups (which users and devices they manage), and scope tags (which objects they see).
  • Scope tags limit admins to objects with matching tags, for example devices and policies for Europe only.
  • Multi-admin approval (access policies) requires a second admin to approve app deployments, scripts, or device wipes.

Compliance & access

  • Compliance policies set requirements (BitLocker, OS version, password, Defender risk level). Actions for noncompliance: mark noncompliant (immediately by default), email, remote lock, retire, after a grace period.
  • Tenant setting: "Mark devices with no compliance policy assigned as" Compliant (default) or Not compliant. Compliance status validity period default 30 days.
  • Conditional Access grant "Require device to be marked as compliant" blocks access from noncompliant or unmanaged devices.
  • Windows Hello for Business: tenant-wide during enrollment, or a policy for targeted groups. Hybrid environments: cloud Kerberos trust is the recommended deployment model.
  • Windows LAPS with Intune: Account protection policy, backup to Entra ID (enable LAPS in Entra device settings) or AD. View the password in Intune or Entra. Remote action to rotate.
  • Local user group membership (Account protection) adds or replaces members of local groups such as Administrators.
05 · Manage & maintain · 25–30%

Manage & maintain cheat sheet

Autopilot modeWho's at the deviceNotes
User-drivenThe end userMost common. Entra join, or hybrid join with the Intune Connector for Active Directory.
Pre-provisioningTechnician first, then userFormerly "white glove." Press the Windows key 5 times at OOBE. Device apps and policies install before shipping. Needs TPM 2.0 and a physical device.
Self-deployingNobodyKiosks and shared devices. No user affinity. Needs TPM 2.0 attestation and Entra join.

Autopilot details

  • Register devices by hardware hash (CSV import or Get-WindowsAutopilotInfo), or have the OEM/reseller register them.
  • Autopilot device preparation (newer): no hardware hash pre-registration, uses a device security group and enrollment time grouping, simpler setup. Deployment profiles (classic) are needed for pre-provisioning, self-deploying, and hybrid join.
  • Device name template: %SERIAL% or %RAND:x%, 15 characters max. Not supported for hybrid join (use the domain join profile prefix instead).
  • Enrollment Status Page: shows progress and can block device use until required apps and policies install. Can block only on selected apps. Default timeout 60 minutes.
  • Autopilot Reset (remote or local): returns a device to a business-ready state, keeps Entra join and enrollment, and removes personal files and apps.

Windows upgrades & Windows 365

  • Windows 11 needs TPM 2.0, UEFI with Secure Boot, and a supported CPU. Check readiness in the Endpoint analytics Work from anywhere report.
  • Upgrade with a feature update policy (target a specific version, such as Windows 11 24H2).
  • Pro to Enterprise: Windows subscription activation with an E3/E5 license, no reinstall or reboot.
  • Windows 365 Cloud PCs: provisioning policies define join type (Entra or hybrid), network (Microsoft-hosted or an Azure network connection), and image (gallery or custom).
  • Windows Backup for Organizations: back up settings and Store apps through Intune, then restore them during OOBE on a new device.

Configuration profiles

  • Settings catalog is the main profile type, with thousands of settings for Windows, macOS, and iOS.
  • Group Policy analytics: import GPO XML backups to see which settings have MDM equivalents, then migrate them to a settings catalog profile.
  • Imported ADMX templates for third-party apps. Custom OMA-URI for settings not in the catalog.
  • Two profiles that set the same setting to different values cause a conflict, and neither value applies until you fix it.
  • Assignment filters include or exclude devices in an assigned group by properties (model, OS SKU, ownership, enrollment profile). Evaluated at check-in.
  • Specialty devices: Teams Rooms, HoloLens 2, and Zebra (MX profiles) have their own profile types.

Intune Suite add-ons

  • Endpoint Privilege Management: standard users elevate specific apps. Elevation types: automatic, user confirmed (with justification or auth), or support approved. Uses an elevation settings policy plus elevation rules.
  • Enterprise App Catalog: prepackaged Win32 apps from Microsoft with automatic detection and install info.
  • Remote Help: helpdesk screen sharing and control with RBAC and audit logs.
  • Cloud PKI: cloud root and issuing CAs that issue certificates through SCEP profiles, with no NDES server or connector.
  • Microsoft Tunnel for MAM: VPN for unenrolled iOS and Android devices running protected apps.
  • Advanced Analytics: device query (KQL), anomaly detection, battery health, enhanced inventory.

06 · Protect devices · 15–20%

Protect devices cheat sheet

Endpoint security policies

  • Antivirus: Defender settings, exclusions, tamper protection.
  • Disk encryption: BitLocker (Windows) and FileVault (macOS). Silent encryption needs a TPM and "Allow standard users to enable encryption during Autopilot". Recovery keys back up to Entra ID, and users can self-serve them from the Company Portal or My Account.
  • Firewall: Defender Firewall profiles and rules.
  • Attack surface reduction rules: start in audit mode, then block or warn.
  • Security baselines: Microsoft's recommended configurations (Windows, Defender for Endpoint, Edge, Microsoft 365 Apps).
  • App Control for Business: allow-list code. Use the Intune Management Extension as a managed installer so Intune-deployed apps are trusted.

Defender for Endpoint

  • Turn on the Intune connector in the Defender portal and the MDE connector in Intune.
  • Onboard devices with an EDR policy that uses the onboarding package from the connector.
  • Compliance setting "Require the device to be at or under the machine risk score" (Clear, Low, Medium, High). Combined with Conditional Access, a compromised device loses access.
  • Investigate and triage incidents in the Defender portal.

Windows updates

  • Update rings: deferral for quality (0–30 days) and feature (0–365 days) updates, deadlines, grace period, and pause (up to 35 days).
  • Feature update policy: keep devices on, or move them to, a specific Windows version.
  • Quality update policy: expedite a security update to devices that are behind, bypassing ring deferrals.
  • Driver update policy: approve drivers and firmware manually or automatically.
  • Windows Autopatch: Microsoft-managed update service using rings (Test, First, Fast, Broad). Needs Windows Enterprise E3 or higher.
  • Hotpatch (Windows 11 Enterprise 24H2+): security updates without restarts in most months. Enable in a Windows quality update policy, with VBS on.

Apple, Android & delivery

  • iOS/iPadOS and macOS updates: Settings catalog declarative software update settings (enforce a version by a date).
  • Android: system update configuration for fully managed and dedicated devices (automatic, postponed, windowed), and FOTA (Samsung E-FOTA, Zebra LifeGuard) for firmware.
  • Delivery Optimization download modes: HTTP only (0), LAN (1, default), Group (2) by group ID across subnets, Internet (3), Simple (99), Bypass (100). Connected Cache caches content locally.
  • Monitor with Windows Update reports in Intune (requires Windows diagnostic data enabled).
07 · Apps · 15–20%

Apps cheat sheet

Microsoft 365 AppsBuilt-in app type. Choose apps, architecture, update channel, or upload an Office Deployment Tool XML.

Enterprise App CatalogMicrosoft-packaged Win32 apps (Intune Suite).

Assignment

  • Required: installs automatically. Available for enrolled devices: offered in the Company Portal. Uninstall: removes it. Available with or without enrollment: for app protection scenarios.
  • Monitor per-device and per-user install status. Win32 logs live in C:\ProgramData\Microsoft\IntuneManagementExtension\Logs.
  • Quiet time policies mute Outlook and Teams notifications on mobile during set hours.

Microsoft 365 Apps

  • Update channels: Current, Monthly Enterprise, Semi-Annual Enterprise (most validation time).
  • During Autopilot, deploy M365 Apps as a required app that the ESP blocks on.
  • Microsoft 365 Apps admin center (config.office.com): Cloud Policy service applies Office policies to users on any device, including unmanaged ones. Also inventory, servicing profiles, and security update status.

App protection policies (MAM)

  • Protect work data inside apps (Outlook, Teams, Edge, OneDrive) on enrolled or unenrolled devices.
  • Data protection: block copy/paste and "Save as" to unmanaged apps, require encryption, restrict backups.
  • Access requirements: app PIN or biometrics, work account sign-in.
  • Conditional launch: block or wipe on jailbroken/rooted devices, minimum OS or app version, max offline time.
  • Selective wipe removes only app data.
  • Conditional Access grant "Require app protection policy" ensures only protected apps can access data.

App configuration policies

  • Push settings to an app, such as an Outlook account setup or a default URL.
  • Managed devices channel: delivered through MDM (enrolled iOS/Android devices).
  • Managed apps channel: delivered through the Intune App SDK, so it works on unenrolled devices.
  • App protection = protect data. App configuration = preconfigure settings.
08 · Automation, monitoring & reporting · 10–15%

Operations cheat sheet

Automation

  • Microsoft Graph PowerShell SDK: Connect-MgGraph -Scopes DeviceManagementManagedDevices.ReadWrite.All, then cmdlets such as Get-MgDeviceManagementManagedDevice.
  • Use app registrations with application permissions for unattended scripts. Grant least-privilege Graph scopes.
  • Custom compliance (Windows): a PowerShell discovery script plus a JSON file that defines the rules and remediation messages.
  • Security Copilot agents in Intune analyze vulnerabilities, policies, and device performance, and make recommendations an admin reviews before acting.

Endpoint analytics

  • Startup performance: boot and sign-in times, slow startup processes.
  • App reliability: crash counts and app health scores.
  • Work from anywhere: cloud readiness and Windows 11 readiness.
  • Remediations: detection + remediation script pairs on a schedule (requires Windows Enterprise E3/E5 or equivalent licensing).
  • Device scope and baselines let you compare groups to org baselines.

Reports & health

  • Reports blade: device compliance, configuration, app install, update reports, and exports through the UI or Graph.
  • Send Intune audit and operational logs to Log Analytics through diagnostic settings for workbooks and longer retention.
  • Tenant admin → Tenant status: service health, connector status, and message center posts.
  • Audit logs show who changed which policy and when.

10 · Traps

Classic traps

Retire keeps personal data. Wipe doesn't. BYOD questions almost always want Retire or a selective app wipe.
Delete does nothing on the device. It only removes the record from Intune.
App protection works without enrollment. If users won't enroll personal phones, the answer is MAM, not compliance policies.
Self-deploying and pre-provisioning need TPM 2.0, and they don't work in VMs without vTPM attestation support.
Device name templates don't apply to hybrid join. Use the domain join profile prefix.
The APNs certificate must be renewed with the same Apple ID. A new certificate forces every Apple device to re-enroll.
Scope tags limit what admins see; scope groups limit what they can manage. Questions about "only see European devices" want scope tags.
Two profiles setting the same value differently → conflict, and neither applies.
LOB apps can't have dependencies or supersedence. Use Win32.
Remediations need Windows Enterprise E3/E5 (or equivalent) licensing, not just Intune.
Devices with no compliance policy are Compliant by default. Change the tenant setting to treat them as noncompliant.
Android device administrator is legacy. Choose an Android Enterprise profile.
